# 2026-09-16 工作日志

## PocketBay 部署可行性研究（AITrader / InvestProject）

**背景**：调研 https://pocketbay.com/deploy 及其机器可读手册 https://pocketbay.com/api/deploy/instructions，评估 AITrader 能否部署到 PocketBay，需要哪些改动。本轮只做研究分析，未改代码。

### PocketBay 关键事实（已确认）
- 一次上传 = 一个项目 = 一个 `https://<slug>.pocketbay.app` 域名；禁止拆成前后端两个项目/两个域名。
- 支持类型：static / nextjs / node / python / dockerfile（项目根放 Dockerfile）。
- 硬性要求：动态应用必须读环境变量 `PORT` 并绑定 `0.0.0.0`；健康接口可选，不要求 `/health`。
- 持久化：动态应用挂 `/data` 并注入 `POCKETBAY_DATA_DIR=/data`；托管 PG 时注入 `DATABASE_URL`（Redis 不托管）。
- 配置迁移：配对页批准的配置加密入库，运行时**按原路径只读挂载**（`upload_mode=package`）。
- 无 cron / 多进程 worker 能力（手册未提供），Compose 里的 DB/worker 不会被执行。
- 默认排除：`.git` `node_modules` `.venv` `__pycache__` 本地 DB 文件、未批准的 `.env`。
- 部署失败给 `error_logs`（优先信）+ `error_category` / `repair_hint`；总尝试 ≤3 次。

### 项目现状事实（已核实）
- 类型判定：**python**（FastAPI + Jinja2 模板 + StaticFiles，单进程可出页面+接口）。前端全部用相对路径 `fetch('/api/...')`，只有 Chart.js 走 CDN → 单域名无跨域问题。
- `web.py` 硬编码 `host="127.0.0.1"`, `port=8000` → **必须改**。
- `requirements.txt` **缺** fastapi / uvicorn / jinja2 / baostock / tushare（AST 扫描确认）；多出未使用的 scipy、pytest、pytest-mock（构建负担）。
- DB：SQLite `data/simulation.db`（settings.yaml + Repository 默认值），`create_database()` 用 `create_engine(f"sqlite:///{path}")`，**不支持 DATABASE_URL**。
- 运行时写盘（4 处，全在 config/ 下）：
  - `routes/control.py:55` → `config/traders.yaml`
  - `routes/watchlist.py:145,162` → `config/watchlist.yaml`
  - `routes/strategies.py:175` → `config/traders.yaml`
  - `analysis/evolution.py:75` → `config/traders.yaml`（config_path 相对 CWD）
- 定时交易：APScheduler 只由 `cli.py schedule` 启动，web 进程**不跑调度** → 部署后没有自动交易。
- 空库问题：`repo.init_traders()` 只在 `cli.py init` 调用；`Simulator.run_daily` 发现无操盘手直接 `return {}` → 本地 DB 被排除出包后，线上首屏是空看板。
- 无 dotenv 加载：环境变量只从进程环境读（main.py 的 AITRADER_USERNAME/PASSWORD、TUSHARE_TOKEN；llm_reporter/analysis 的 ANTHROPIC_*）。
- 数据源强依赖中国大陆行情端点：`hq.sinajs.cn`、baostock、akshare(Eastmoney) → PocketBay 节点若在境外有超时风险；dashboard 首页会实盘拉 510300 近 90 日数据。

### 结论
可以部署（python 类型），但必须做 P0 四项改动：补依赖、改 PORT/0.0.0.0、可写状态迁 `/data`、首启初始化 DB。P1：应用内调度替代 CLI 调度 + TZ=Asia/Shanghai。P2：可选托管 PG（需给 `create_database` 加 DATABASE_URL 分支）、补 `/health` 轻量端点（现有 `/api/health` 会实打网络，不适合做探活）。

### 验证结果

### 关键决策（安全）
**不申报 `.env`、密钥不进包**。依据：平台文档明示"打包进源码的密钥会影响别人基于你的项目创建专属副本"。本项目 LLM 接口在无 key 时已优雅降级（周报返回提示、AI 分析返回"暂不可用"，不 500），所以部署形态定为「看板+模拟交易全功能，LLM 关闭」。

## 实际部署到 PocketBay（同日晚，最终成功）

**结果**：线上地址 <https://aitrader-dashboard.app.workbuddy.host/>（appId `wbapp_…` 已登记，`sandboxId=d682aa28e8414c3a973768af2c73f16b`）。
部署参数：`language=python` / `port=8000` / `installCmd=pip install -r requirements.txt` / `startCmd=python web.py`。
为满足"改动必须进 git"，先 `git init`（仓库此前只有 `.gitignore` 未初始化），4 个 commit：`a818bdb` → `e47508f` → `213a3c1` → `9dc8c6a`。

### 三次尝试、两次失败的根因（都是"启动/探活路径上的不受控网络等待"）

**失败一**：`service did not become reachable on port 8000 within 60s`。
日志里应用其实**已启动成功**（Uvicorn 正常、端口 LISTEN），是探活请求拿不到响应。
根因：`GET /` 同步走 `_calc_market_env()` → baostock，`bs.login()` 无超时参数，沙箱内无限阻塞（本机复现 80s+）。
修复：市场环境改"先返回缓存/占位 + 后台刷新"（10min TTL、单飞、退避、看门狗）。首屏 **80s+ → 0.07s**。

**失败二**：`port 8000 NOT listening`，日志停在 `Waiting for application startup.`——应用根本没起来。
根因：`engine/factory.py:build_data_provider()` 在 **lifespan 里同步探测**实时行情（拉茅台现价）决定真实源还是 mock，而 sina 探测路径会顺带调 baostock 补指标 → 同样无超时 → 启动永不完成。
修复：探测加 15s 上界（`run_with_timeout`）超时回落 mock；调度器装配包 `try/except`，**装配失败绝不阻断 web 启动**。
注意：探测预算刻意给 15s 而非更短——过紧会在"网络慢但数据可用"时误回落 mock，写入虚构价格比多等几秒严重得多。

**第三次补充修复**：线上三个数据源全不可达时页面永远显示「行情加载中」。
根因：沙箱里 baostock 是**永久挂起**而非快速失败，后台线程从不返回，失败结果写不进缓存。
修复：后台计算也加 120s 上界，超时按失败记录 → 页面如实转为「行情离线」并按指数退避重试。

### 其它实测事实
- **`POCKETBAY_DATA_DIR` 未注入**（疑似未挂持久卷），可写目录回落容器内 `/workspace`；`DATABASE_URL` 也未注入。
- **`PORT` 会注入** → 已用它作为"是否在平台运行"的判据来启用进程内调度（改 `web/main.py`）。
- **本地 `data/simulation.db` 被打进了包**：线上首屏带着本地持仓与净值历史（总资产 ¥62431、+4.05%）。反过来线上交易不在持久卷上，重部署可能被包内旧库覆盖。
- **沙箱访问不到大陆行情端点**：线上 `GET /api/health` = `{"sina":false,"baostock":false,"tushare":false}`。所以线上是「看板 + 历史数据」可用，实时行情/自动交易/选股不可用。
- 另顺手修：`_calc_market_env` 失败分支缺 `index_price`，模板 `"%.2f"|format(...)` 会抛错导致 `/` 500。
- `/recommendations` 本机耗时 18~27s（逐标的串行 baostock 登录），已知慢页，未处理。

### 可复用结论
1. 平台报"不可达"时先看日志有没有 `Application startup complete`——"卡住"和"没起来"是两种病。
2. 调用 baostock / akshare 这类无超时参数的第三方库，默认用 `runtime.run_with_timeout` 设界。
3. 不要在可能阻塞的调用外面替换全局 `sys.stdout`：`bs.login()` 外原本包着 `sys.stdout = io.StringIO()`，一挂死全局重定向永久生效、进程日志整段静音（相关替换已从 `src/data/sina_client.py` 移除）。
3. 未执行真实 PocketBay 部署（配对流程需用户在浏览器确认）
