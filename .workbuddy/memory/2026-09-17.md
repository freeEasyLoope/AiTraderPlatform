## 站内跳转改为异步局部加载（用户诉求：切换页面"没反应"像断网）

### 根因
站内跳转在 PocketBay 的 embed 帧内是**整页导航**。请求一旦被挂住（应用被平台休眠 /
冷启动 / 服务端首次计算行情），旧界面完全静止 → 用户以为网断了。上一版只加了遮罩
提示，跳转本身仍是整页刷新，慢的时候依旧静止。

### 落地
- `base.html` 引入两个交换边界：`#page-root`（内容，包住 `.container`）、
  `#page-scripts`（页面脚本）。**必须分开** —— `screening.html` 的 `<script>` 写在
  content 块里；且 `innerHTML` 插入的 `<script>` 不执行，需手动按块重放。
- 新增 `asyncNav` 引擎：拦截站内链接 → 立即加载态 → `fetch` 目标页 HTML →
  只替换内容区 → 按序重放页面脚本 → `pushState` + 自行更新导航高亮。
- 加载态：顶部不确定进度条 + 内容淡化（旧内容保留不白屏）+ 分阶段文案
  （正在加载 → 正在计算行情数据 → 应用可能正在唤醒，带已等待秒数）+ 60s 安全阀。
- 悬停预取：260ms 防抖、单飞串行、10s 命中窗口。
- 任何环节不符合预期 → 回退整页导航；表单提交语义不变，只补反馈。

### 两个必须记的技术点
1. **页面脚本顶层 `let`/`const` 是致命陷阱**：同一文档二次注入会抛
   `Identifier 'x' has already been declared` → **整个脚本不执行**，复访该页
   功能静默失效（不报错到页面、只在控制台）。`control.html` / `reports.html` 命中。
   解法：`deLexicalize()` 把**行首**（零缩进）let/const 降级为 `var`
   （函数体内块级作用域不动，语义不变）；另挂一次性 error 守卫，命中确定性
   SyntaxError 就回退整页导航。
2. **PocketBay 的 embed 帧内 `fetch()` 能拿回应用 HTML**：网关按 `Sec-Fetch-Dest`
   分流，XHR/fetch 是 `empty`，走应用而非外壳页。所以异步局部加载在平台上成立
   —— 这是本次能做的前提，已用真实浏览器在线上确认。

## 修「加载提示永不消失」与「漏斗点不进去」（用户反馈）

线上两个症状，根因都是「不报错、不 500、只是体验坏掉」，此前所有测试都通过。

### ① 加载提示永久盖屏
`#navLoading` 由 JS 创建后长期复用，`hideLoading()` 只做「移除 `.on`」，
**但 CSS 里根本没有 `#navLoading.on` 规则，基态又是可见的**
（`position:fixed` 全屏 + `rgba(0,0,0,.55)` + `blur(2px)`）。
→ 去掉类名毫无视觉变化，遮罩从第一次跳转起永久留着，整站像蒙了一层。
教训：**断言类名 ≠ 断言计算样式**。之前的 E2E 只检查 `classList` 不含 `on` 就判通过，
所以 31/31 全绿也没发现。现在改为看 `getComputedStyle` 的 `visibility/opacity`。
改法：基态 `visibility:hidden` + `opacity:0`（visibility 用 0s 延迟过渡做淡出），
`.on` 才显示；并**去掉全屏深色模糊**（把"加载慢"放大成"网站挂了"），
改成导航栏下方（`top:68px`）居中的胶囊提示，内容区淡化从 0.38 放宽到 0.5。

### ② 漏斗 307 → 明文 http → 被浏览器按混合内容拦掉
`screening.py` 用了 `APIRouter(prefix="/screening")` + `@router.get("/")`，
真实路径是 `/screening/`，访问 `/screening` 得到
`307 Location: http://aitrader--e.pocketbay.app/screening/`。
应用在平台 https 网关后（未传 `X-Forwarded-Proto` 时 Starlette 按明文 http 生成绝对 URL），
https iframe 内跟随该重定向会被拦 → 表现「点了没反应 / 进不去」。
**全站只有这一个页面带尾斜杠**。改法：去掉 prefix、路径写全量
（与 `/signals`、`/reports` 一致），`/screening` 与 `/screening/` 都直接 200。
教训：**导航项目标一律不允许依赖 3xx**，整页刷新会掩盖它、fetch 局部加载不会。

### ③ 平台边缘缓存导致「新页面 + 旧 CSS」
修完部署后线上 `/static/style.css` 仍返回旧内容（`age=1305`、43400B，包内已 45000B）。
原因：应用对 `/static/*` 下发 `max-age=14400`，平台边缘节点照此缓存；
而动态 HTML 是 `no-store` 每次新的 → **最长 4 小时内样式改了却不生效**，
且因为 HTML 确实变了，极容易被误判成"改动没起作用"。
改法：`deps.py:static_version()`（style.css 的 sha256 前 12 位，进程内缓存）
注册成 Jinja 全局，`base.html` 引用 `/static/style.css?v=<指纹>`。
**以后凡是改 `/static/` 下的资源，必须确认引用处带指纹。**

### ① 修「运行漏斗」报错 `Unexpected token '<'`（已修并验证）
根因：`screening.py` 原实现用 `try/except asyncio.TimeoutError` 同步等待漏斗跑完，
`timeout=300` 时重网络抓取超过平台网关超时 → 网关回 HTML 502/504；且非 Timeout 异常
逃逸 → Starlette 默认 500 HTML 页。前端 `resp.json()` 撞上 HTML 就抛这个错。
改法：改成 **异步任务 + 轮询** —— `GET /screening/api/run` 立即返回 `{ok,task_id,status}`，
后台 `threading.Thread` 跑，新增 `GET /screening/api/status?task_id=` 永远回 JSON
（running/done/error/unknown）。所有 HTTP 响应都是短 JSON，**不再可能回 HTML**。
`screening.html` 相应改为 `pollScreening()` 每 1.5s 轮询、180s 上界。已验证。
