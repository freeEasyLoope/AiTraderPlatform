# AITrader 场景化走查与优化清单

> 日期：2026-09-17　走查方式：以「老股民」「新股民」两类真实用户视角，逐页走查
> 全部功能页（总览 / 策略 / 信号 / 自选 / 风控 / 挑战 / 漏斗 / 设置 / 控制 / 个股 /
> 引导），核对 UI、交互、布局、功能，并汇总可落地的优化项。
> 走查基于源码与模板（`src/web/templates/*`、`src/web/routes/*`、`static/style.css`）。

---

## 一、老股民视角（诉求：效率、深度、对数据的信任）

### 1. 找不到「直接查一只股票」的入口
全站没有全局搜索框。要看某只股票，只能从「自选池」「持仓表」里点进去，或手改 URL
（`/stock/600000`）。老股民最高频的动作就是「报代码直接看」，当前路径太长。

- **优化**：在导航右侧或首页放一个搜索框，支持 代码 / 名称 / 拼音首字母，回车直达
  `/stock/<code>`。至少先支持代码。

### 2. 涨跌配色与 A 股习惯相反（信任杀手）
`base.html` 的个股弹窗里 `cls = p.change_pct >= 0 ? 'green' : 'red'` —— **涨用绿、跌用红**，
是欧美惯例；A 股用户看到「红跌绿涨」会本能地不信任数据。

- **优化**：改为 **红涨绿跌**，并全局统一（含 `.green/.red` 语义类、`translateReason`、
  温度计、进度条）。注意 `.red/.green` 同时被错误/成功语义复用，需逐个三元式翻转，
  不能直接交换 CSS 变量。
- 说明：此项此前已记录为「待用户决定」，建议本次一并拍板。

### 3. 数据真伪不透明
页面有「来源日期」药丸，但当实时源不可用、回落 Mock/延迟数据时，界面**没有任何显式警示**
（只有导航右侧一个 `🟢/🔴` 小灯）。老股民最怕「拿模拟价当真实价看」。

- **优化**：当 `/api/health` 的 `realtime=false` 时，在页面顶部显示一条常驻横幅：
  「⚠ 当前实时行情不可用，展示的是模拟/延迟数据，仅用于功能演示」。数据源状态灯
  也建议从 emoji 点改为带文字的胶囊。

### 4. 控制台改参「改完不能就地验证」
`control.html` 每个操盘手是折叠参数卡，能改参、保存，但改完想去验证只能跳到「策略实验室」
重新手配一遍回测参数，两个动作割裂。

- **优化**：参数卡上加「用此参数回测」按钮，一键跳到策略实验室并预填该操盘手参数。
- **次优**：保存后回显「上次修改时间 / 由谁改」，并给「恢复默认」入口。

### 5. 表格缺少排序 / 筛选
持仓表、交易记录、选股结果、信号列表都只有固定顺序，没有列排序，也没有「只看我的持仓 /
只看某个策略」的过滤。

- **优化**：给关键表格加点击表头排序；信号/交易记录加「策略」「方向」过滤与
  「只看自选/持仓」开关。

### 6. 个股详情页能力偏薄
`stock.html` 有最新价 / PE / PB / 估值温度计 / 走势 / 新闻 / holders，但：

- 没有「加入自选」按钮（看中了要从自选页反向操作）；
- 没有 K 线周期切换（日 / 周 / 月）、没有成交量副图；
- 新闻区没有「按时间倒序 / 去重」说明。

- **优化**：补「加入 / 移出自选」按钮 + 周期切换 + 成交量副图。

### 7. 回测缺基准对比
「策略实验室」有回测与双组对比，但没有与基准（沪深300 / 中证500）的对比曲线，
老股民无法判断「是策略强还是大盘涨」。

- **优化**：回测结果叠加基准曲线 + Alpha / 超额收益数值。

## 二、新股民视角（诉求：被引导、看得懂、敢操作）

### 1. 「新手引导」形同虚设（已确认缺陷）
`/onboarding` 路由存在、页面完整，但 **导航里没有入口，任何页面也不会自动跳转过去**
（`aitrader_onboarding` 标记只在 onboarding.html 内部读写）。首页那个「? 新手引导」按钮
打开的是 `#helpBox` 说明框，**不是** 这个引导流程。结果：新用户除非手敲 URL，否则永远
看不到这条专为新人设计的三步引导。

- **优化**：首次访问（未完成引导）时，由总览页自动跳转或弹出引导入口；并在导航加
  「新手引导」入口（或在设置里提供）。

### 2. 移动端「名词提示」失效（已确认缺陷）
`initTermTips()` 只绑定了 `mouseover / mouseout / focusin / focusout`。手机上没有 hover，
而 `.term` 是普通 `<span>` 不可聚焦 → **触屏用户点术语不会有任何提示**，而 page 上
术语（市盈率、金叉、夏普比率…）密度很高。

- **优化**：给 `.term` 加 `tabindex="0"` 并支持 `click/touchstart` 切换显示；
  或移动端改为点击弹层。

### 3. 空状态只「告知」，不「带路」
漏斗结果、周报、交易记录为空时只显示「暂无…」，没有「下一步做什么」。

- **优化**：空状态补主 CTA（如「去自选池加一只股票」「运行选股漏斗试试」）。

### 4. 危险操作缺少统一的后果说明
「触发交易」「再平衡」「运行漏斗」等有副作用的按钮，二次确认文案不统一、部分直接执行，
新用户不敢点、或误点。

- **优化**：所有写操作统一走 `showConfirm`，文案说清「会发生什么 / 影响哪些账户」，
  且明确标注「模拟盘」。

### 5. 结果缺「白话结论」
漏斗 / 信号结果是一堆表格，缺少一句「所以呢」。虽有 `translateReason()`，但覆盖有限。

- **优化**：在结果顶部生成一句自然语言摘要（如「筛出 12 只，其中 5 只低估值 + 金叉，
  建议重点看这几只」）。

### 6. 亏损时的情绪与解释
亏损用醒目红字，但没有「为什么亏」的解释入口，新用户容易慌。

- **优化**：亏损项旁提供「看看原因」链接到对应策略画像 / AI 周报。

## 三、通用布局与信息架构

### 1. 顶栏偏拥挤
导航共 11 项（总览 / 策略 / 信号 / 自选 / 风控 / 挑战 / 漏斗 / 设置 / 控制），
小屏需横向滚动。主题切换 4 个圆点又占一块。

- **优化**：按语义分组（行情 / 研究 / 账户 / 设置）或折叠「更多」；主题切换迁到
  设置中心「外观」区块，带配色预览与名称（圆点无文字，新人不知哪套是啥）。

### 2. 缺少全局帮助 / 文档入口
除每页的 `? 指标解释` 外，没有集中的「帮助 / 使用说明 / 术语表」入口。

- **优化**：在设置里加「帮助与术语」区块，或导航加一个 `?` 入口。

### 3. 骨架屏未广泛使用
`style.css` 已定义 `.skeleton`，但慢网络下首屏基本是「空白 → 突然全部出现」。

- **优化**：给数据量大的卡片（行情概览、排行）加骨架屏。

### 4. 主题切换时图表不即时重绘
图表文本 / 网格色在创建时从 CSS 变量读取，但 `themechange` 事件没有订阅者，
**切主题后不刷新、图表颜色要等下次页面跳转才更新**。

- **优化（可选）**：让各页图表订阅 `themechange` 重新 `update()`。

## 四、优先级汇总

| 级别 | 项 | 涉及位置 | 影响 |
|---|---|---|---|
| **P0** | 涨跌配色改为红涨绿跌并全局统一 | `base.html`、各模板三元式、`.green/.red` | 老股民信任 |
| **P0** | 新用户引导入口（onboarding 目前无入口） | `base.html` 导航 / 总览跳转 | 新用户上手 |
| **P0** | Mock/延迟数据顶部显式警示 | 全局（读 `/api/health`） | 数据可信 |
| **P0** | 移动端术语提示支持点按 | `base.html` `initTermTips` | 新用户理解 |
| **P1** | 全局股票搜索（代码/名称） | 导航 / 首页 | 老股民效率 |
| **P1** | 控制台「用此参数回测」一键联动 | `control.html`→`strategies.html` | 闭环验证 |
| **P1** | 表格排序 + 自选/策略筛选 | 持仓 / 交易 / 信号 / 漏斗 | 效率 |
| **P1** | 个股页「加入自选」+ 周期切换 + 量图 | `stock.html` | 能力补齐 |
| **P1** | 写操作统一二次确认（后果说明） | 全局 | 安全感 |
| **P2** | 导航分组/精简；主题切换迁入设置 | `base.html`、`settings.html` | 信息架构 |
| **P2** | 空状态补 CTA | 各空态模板 | 引导 |
| **P2** | 回测叠加基准曲线 + Alpha | `strategies.html` | 深度 |
| **P2** | 结果白话摘要 | 漏斗 / 信号 | 可读性 |
| **P2** | 骨架屏；图表订阅 themechange | `style.css`、各页脚本 | 观感 |

> 备注：P0 第 2、4 项与本轮走查新确认的两处**真实缺陷**一致，建议优先处理。
